# Clarification Policy

## Goal

澄清的目标是消除会改变结果的歧义，而不是让用户填写需求表。

## Ask when

只有以下情况优先澄清：

1. 存在多个明显不同的目标。
2. 关键范围无法确定。
3. 用户给出的约束互相冲突。
4. 执行会产生高风险、不可逆或明显超出预期的结果。

## Do not ask when

以下信息优先自行获取：

- 项目文件路径
- 已存在的技术栈
- 测试框架
- 项目约定
- README / CLAUDE.md / AGENTS.md 中已有的信息
- 可以通过代码、配置、Git 状态或工具确认的信息

## Question design

一次只问阻塞性问题。优先给出 2～5 个可选项，并允许用户用自然语言回答。

坏例子：

> 请提供项目背景、目标用户、技术栈、约束、验收标准……

好例子：

> 你说的“优化”主要指哪一类？
> A. 性能
> B. 测试
> C. 代码质量
> D. 架构
> E. 全部

用户回答后，不要求重新描述原需求。
